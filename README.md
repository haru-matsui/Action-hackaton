# PM Radar — инструмент управления рисками и изменениями в проекте

Работающий MVP для руководителя проекта: создаёте проект с задачами, сроками,
ответственными и зависимостями — а система на лету пересчитывает график и
показывает **последствия любых изменений**: что сдвинется, вышел ли проект за
дедлайн, какие задачи под угрозой и что делать.

Главный вопрос продукта: **«Если сейчас что-то изменится, что произойдёт с
проектом и на что мне обратить внимание?»**

## Быстрый запуск

На Windows дважды нажмите `START-Windows.bat`. Скрипт установит Flask при
необходимости и откроет приложение по адресу `http://127.0.0.1:5000`.

Демонстрационный проект загрузится автоматически. Для показа сценария откройте
задачу «Разработка backend», измените длительность с 10 до 17 дней, нажмите
«Оценить последствия», затем «Сохранить».

## Запуск в Docker

```bash
docker compose up --build
# открыть http://localhost:5000
```

Для нейросетевых ответов в контейнере задайте `OPENROUTER_API_KEY` в окружении
перед запуском. Без ключа интерфейс явно показывает резервный расчётный ответ.

Или одним контейнером:

```bash
docker build -t pm-radar backend
docker run -p 5000:5000 -v pm-data:/app/data pm-radar
```

## Запуск без Docker

```bash
cd backend
pip install -r requirements.txt
python app.py            # http://localhost:5000
```

`backend/data/db.json` — исходные демонстрационные данные. Изменяемая база
хранится в `%LOCALAPPDATA%\PM-Radar\data\db.json` на Windows или в каталоге,
указанном переменной `DATA_DIR`. В Docker это volume `pm-data`.
При первом старте автоматически создаётся **демонстрационный проект
«Запуск CRM-платформы»**: 10 задач, несколько зависимостей, 5 ответственных,
выполненные и незавершённые задачи; изменение «Разработка backend» напрямую
влияет на все последующие работы.

## Что реализовано

1. **Создание проекта** — название, дедлайн (в рабочих днях), задачи со
   сроком, ответственным и статусом (к выполнению / в работе / выполнено).
2. **Связи между задачами** — зависимости «B после A», задаются чекбоксами в
   форме задачи; цикл в графе отклоняется с понятной ошибкой.
3. **Управление проектом** — добавление/редактирование/удаление задач, смена
   сроков, статусов, ответственных и зависимостей.
4. **Анализ последствий изменений** — движок CPM (ранний/поздний старт,
   резерв времени, критический путь). Любое изменение сначала проходит через
   **предпросмотр последствий**: какие последующие задачи сдвинутся и на
   сколько, изменился ли общий срок, нарушен ли дедлайн, какие задачи под
   угрозой, требуется ли вмешательство.
5. **Представление проекта** — показатели проекта и три связанных представления:
   линия времени с дедлайном, таблица с расчётными резервами и SVG-граф
   зависимостей. Критический путь выделен фиолетовым, риски — янтарным,
   завершённые задачи — зелёным.

## Контр-фича: ИИ-ассистент руководителя проектов

Встроенный чат-ассистент **не считает сам** — он получает готовые результаты
CPM-движка и симуляций и переводит их на человеческий язык:

- **объясняет последствия** каждого применённого изменения (авто-комментарий
  в чате после применения правки задачи);
- **предлагает решения**: переназначить ответственного (видит, что один
  сотрудник ведёт несколько критических задач), разбить задачу на подзадачи,
  согласовать сдвиг дедлайна;
- **отвечает на вопросы «что будет, если…»** в режиме симуляции:
  «что будет если Тестирование задержится на две недели?»,
  «что будет если Олег Кузнецов уйдёт в отпуск?» — модель отпуска замедляет
  все незавершённые задачи сотрудника на 50% (добавка округляется вверх).
  Это явно обозначенное допущение: даты отпуска и доступность замены неизвестны.
  Сценарий ничего не сохраняет;
- **формирует краткие отчёты**: «дай отчёт по проекту» — статус, готовность,
  выполненные/незавершённые задачи, критический путь, угрозы, вывод о
  необходимости вмешательства.

Подключена **DeepSeek V4.1 Flash через OpenRouter**
(`deepseek/deepseek-v4.1-flash`). Ключ читается сервером из локального файла
`%LOCALAPPDATA%\PM-Radar\ai.json` или переменной `OPENROUTER_API_KEY`.
Он не передаётся браузеру и не включается в EXE. На другом компьютере ключ
нужно настроить отдельно. Нейросеть получает JSON с готовыми расчётами;
у неё нет инструментов записи в проект. Ответы проверяются по схеме и числам.
При ошибке API приложение показывает расчётный ответ с явной отметкой о замене.
В каждом ответе виден его источник. Подробности и ограничения —
[`docs/ai.md`](docs/ai.md).

## Демонстрация основного сценария (2 минуты)

1. Открываете демо-проект → видите timeline: прогноз 29 дн. при дедлайне 30,
   критический путь подсвечен фиолетовым.
2. Кликаете «Разработка backend» → меняете длительность 10 → 17 →
   **«Оценить последствия»**: система показывает +7 дн. по всем
   последующим задачам, выход за дедлайн на 6 дн., список задач под угрозой
   и рекомендации. Изменение ещё НЕ применено.
3. **«Сохранить»** → график перерисовывается, ассистент в чате пишет
   объяснение своими словами.
4. В чате: «Что будет если Олег Кузнецов уйдёт в отпуск?» → симуляция без
   изменения данных + предложение переназначить задачи.
5. «Дай отчёт по проекту» → сводка и вердикт «требуется вмешательство».
6. Меню «⋯» в верхнем правом углу → «Восстановить демо» возвращает исходное
   состояние выбранного проекта для повтора.

## API (кратко)

| Метод | Путь | Назначение |
|---|---|---|
| GET/POST | `/api/projects` | список / создание |
| GET/PUT/DELETE | `/api/projects/<id>` | чтение / обновление / удаление |
| POST | `/api/projects/<id>/impact` | анализ последствий (`apply:false` — предпросмотр) |
| POST | `/api/projects/<id>/simulate` | what-if пакетных изменений без сохранения |
| POST | `/api/projects/<id>/assistant` | чат с ИИ-ассистентом |
| POST | `/api/projects/<id>/reset-demo` | сброс к демо-данным |
| GET | `/api/ai/status` | модель и состояние подключения без ключа |
| GET | `/api/projects/<id>/radar` | риски и нейросетевое объяснение |
| POST | `/api/projects/<id>/sandbox` | виртуальный сдвиг старта, без записи |
| POST | `/api/projects/<id>/checklist` | черновик подзадач |
| POST | `/api/projects/<id>/apply-checklist` | применение согласованного черновика |
| POST | `/api/projects/<id>/explain` | объяснение связей выбранной задачи |
| GET | `/api/projects/<id>/report.md` | текстовый отчёт |

## Структура проекта

```
README.md                  # запуск, сценарий демонстрации и API
docs/
  build-windows.md         # сборка Windows EXE
  compliance.md            # сверка с заданием и ограничения MVP
  ai.md                    # модель, настройка, ограничения и тестирование ИИ
backend/
  app.py                   # Flask API, валидация, хранение, отдача интерфейса
  schedule.py              # граф задач, сроки, резервы и анализ изменений
  assistant.py             # ответы и объяснения ассистента
  ai_features.py           # радар рисков, чек-листы, песочница
  ai_service.py            # OpenRouter, строгая схема, проверка и резервный ответ
  ai_context.py            # структурированные факты для модели
  data/db.json             # начальный демонстрационный проект
  static/
    index.html             # структура страницы и диалоги
    css/app.css            # оформление компонентов и адаптивная компоновка
    js/app.js              # состояние, действия, формы, чат и песочница
    js/api.js              # запросы к Flask API и обработка ошибок
    js/views.js            # показатели, Гант, таблица, граф и последствия
    js/ui.js               # SVG-иконки, форматирование, диалоги, уведомления
  Dockerfile               # контейнерная сборка из тех же модулей
tests/test_api.py          # регрессия демосценария и предпросмотра
tests/test_ai.py           # контракт ИИ, сбои API, симуляции и сохранение
tests/live_ai_smoke.py     # 5 реальных запросов, только с флагом --run
docker-compose.yml         # запуск контейнера и volume данных
PM-Radar.spec              # состав Windows EXE
START-Windows.bat           # запуск из исходников
BUILD-Windows.bat           # пересборка EXE
START-EXE.bat               # запуск dist/PM-Radar.exe
```

`build/` и `dist/` создаются при сборке и не относятся к исходному коду.
Ранее отдельный `pmradar.py` повторял весь backend и HTML целиком; теперь
запуск из исходников, Docker и EXE используют единые файлы.

### Как устроен фронтенд

HTML задаёт оболочку, навигацию и диалоги. `app.js` загружает проект через
`api.js`, хранит состояние экрана и передаёт данные в `views.js` для отрисовки.
`ui.js` содержит общие элементы оформления и экранирование пользовательского
текста. Расчёт сроков остаётся в Python: фронтенд показывает результаты API.

На широком экране ассистент находится справа от плана. На узком — под ним,
а боковое меню открывается кнопкой. График, таблица и зависимости переключаются
вкладками; последствия редактирования показываются прямо в форме задачи.
В песочнице перетаскивание полосы сдвигает начало задачи, сохраняя длительность;
кнопка «Применить изменение» сохраняет задержку старта в проект.
Расчёт показывается сразу, объяснение DeepSeek — после ответа API.
Выбранную полосу можно менять
клавишами ← и →. Объяснение доступно из формы задачи и кнопкой в таблице.

## Сборка Windows EXE

Запустите `BUILD-Windows.bat`; он создаст `dist\PM-Radar.exe`. Старый EXE не
обновляется автоматически при изменении исходников. Подробности — в
[`docs/build-windows.md`](docs/build-windows.md).

## Проверка

После установки `backend/requirements.txt` запустите
`python -m unittest discover -s tests -v`. Проверка покрывает загрузку
интерфейса, демоданные, предпросмотр изменения и добавления задачи, а также
сохранение после применения. Тесты ИИ проверяют JSON-контракт, ошибки ключа,
баланса и сети, отбрасывание неизвестных чисел, сохранность базы при симуляции
и создание подзадач только после подтверждения. Они не обращаются к сети.
Для отдельной проверки реального подключения:
`python tests/live_ai_smoke.py --run` (5 запросов, расходует баланс OpenRouter,
использует временную демонстрационную базу).
